# PTC worker adapter

This optional intrinsic set exposes `ptc_execute(source)` as a serial,
RequireConfirm tool. The operator installs an external interpreter and selects
its executable/argv; no Python runtime is linked into or bundled with the worker.
The optional `tools.intrinsic` allowlist controls registration independently:
select `ptc` and omit `process`, `reading`, and `editing` to use only PTC for
those operations. Omitting the list preserves legacy automatic registration. Program-level confirmation
precedes execution; shell bypass rules never classify Python source.

`PtcRuntime` owns a private ProcessSessionStore, separate from model-visible
process sessions. It launches an argv command directly, writes one JSON request
to stdin and closes stdin. stdout must contain one complete JSON document.
stderr is drained separately from stdout and never parsed as protocol JSON.
The capture budget is 256 KiB shared between the pipes; any capture loss is a
transport failure. Execution responses are limited to 48 KiB plus a newline.
This transport budget does not truncate valid protocol output into a preview.
The interpreter already applies bounded output and final-result previews.

Initialization probes capabilities and inspects the session before worker
admission. A fresh session has no epoch until its first execution receipt; later
requests carry that epoch. No hidden Python program is executed to initialize
state. UUID execution IDs are generated by the host and never reused to replay
uncertain source. A failed boundary/protocol exchange disables execution until
the worker is restarted after operator inspection; handled Python failures keep
the session usable. The worker does not reset or acknowledge recovery implicitly.

All runtime methods run on the application strand. A run stop token sends SIGTERM
to the CLI, whose existing client implementation cancels the correlated daemon
execution and queries its receipt. The worker waits up to 60 seconds for that
settlement; forced client cleanup is reported as unknown, never rollback.
Startup/control clients also have a 60-second deadline. Normal execution has no
worker wall-clock deadline. Shutdown stops and joins the daemon before releasing
the worker session lease. It must succeed before deleting persistence; escaped
external processes are not a containment guarantee.

Response validation checks protocol, identity, typed envelope fields, commit
semantics and exit-code consistency. JSON result contents are opaque. Known
execution failures use exit 1/committed=false; boundary failures use exit 2 and
commit_status=unknown. Nonzero statuses never implicitly retry code. Diagnostics
retain the execution ID and commands_created when available. The display uses
ToolResult metadata, optional output and result blocks, and explicit preview
hints. Internal IDs/revisions are not repeated on ordinary successful results.

`test_ptc_tools` has dependency-free envelope tests and real CLI integration
when SIMPLEX_TEST_PTC is set. The dedicated CI also exercises the complete
Application with a deterministic model and a local WebSocket peer. No API key,
external LLM, or Hub service is needed.

Execution identity and known commit revision are retained in Content.extras under
`simplex.ptc`, without repeating them in ordinary model-visible text. This is
correlation metadata, not a copy of the Monty heap or a replay instruction.

Managed directory removal also acquires ptc/daemon.lock. If a worker crashes or
shutdown fails while its daemon still owns resources, simplex manage refuses
removal as busy rather than deleting a live daemon's state.
